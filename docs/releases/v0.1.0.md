# Flavor Agent v0.1.0 — initial release

Flavor Agent is the governance layer for AI-mediated WordPress changes. AI proposes through bounded WordPress contracts; WordPress approves structural/theme changes through native editor and wp-admin review; Flavor Agent records owned applies server-side and only reverses them when drift checks prove undo will not clobber later edits. The recommendation surfaces are the demonstration; the governance layer is the product.

> Draft these notes into the GitHub release at `https://github.com/henryperkins/flavor-agent/releases/tag/v0.1.0` after tagging `v0.1.0` and attaching the release zip.

## Highlights

- **Governed external applies across four lanes:** external agents can request bounded Global Styles / Style Book applies through `request-style-apply`, bounded page-level `wp_template` structural applies through `request-template-apply`, bounded `wp_template_part` structural applies through `request-template-part-apply`, and bounded post-content block applies through `request-post-blocks-apply`; administrators approve or reject them in `Settings > AI Activity`; approved applies execute server-side with freshness and operation revalidation.
- **Ring III attestation on three of the four lanes:** `external-style-apply-v1`, `external-template-apply-v1`, and `external-template-part-apply-v1` emit signed, externally verifiable attestation envelopes with a public JWKS and live subject-state route. The post-blocks lane is deliberately **not** attested: its non-public `post_content` is incompatible with the public subject-state contract.
- **Review-first safety model:** template, template-part, Global Styles, and Style Book operations are previewed and confirmed before apply; navigation stays advisory-only; content recommendations stay editorial-only; pattern recommendations stay browse/rank-only and are not Flavor Agent-owned apply/undo.
- **Activity, attribution, and drift-safe undo:** executable editor actions and approved external style, template, template-part, and post-blocks applies write server-backed activity records, support scoped undo where the live state still matches, and appear in inline recent-action sections or `Settings > AI Activity`.
- **Native proof surfaces:** block Inspector recommendations, post/page content drafting and critique, pattern-inserter recommendations, Site Editor template and template-part recommendations, navigation guidance, Global Styles recommendations, Style Book recommendations, and the wp-admin AI Activity governance console.
- **WordPress 7.1 Abilities integration:** 35 ability contracts expose recommendation, helper/read, docs-search, preview, style, pattern, template, navigation, infrastructure, and external-apply capabilities with explicit permissions and behavior annotations. Helper/read abilities and the six signature-only `preview-recommend-*` siblings register whenever their core contracts are available; recommendation and external-apply abilities also require the WordPress AI feature gate. The plugin retains a WordPress 7.0 minimum.
- **Thin REST surface:** remaining plugin REST routes cover activity read/write, activity undo, and admin pattern sync; recommendation execution goes through the WordPress Abilities API.
- **Provider-pluggable architecture:** text generation runs through the WordPress AI Client and `Settings > Connectors`; plugin-owned settings cover embeddings, Qdrant, Cloudflare AI Search pattern retrieval, WordPress docs grounding, guidelines, and pattern sync.
- **Jetpack AI fallback (WordPress.com / managed hosting):** where the WordPress AI Client (`ai`) feature plugin cannot be installed, text generation automatically falls back to Jetpack AI over the existing Jetpack connection — no connector or API key required, drawing on the site's Jetpack AI entitlement. The hard `Requires Plugins: ai` header was removed so the plugin activates in this mode, and `Settings > Flavor Agent` shows an **AI Runtime** indicator (`Jetpack AI` / `WordPress AI Client` / `Not available`).

## Providers and external services

Flavor Agent does not contact external services on activation and does not own chat credentials. External calls happen after administrator configuration or an explicit authorized user action.

| Capability                      | Supported path                                                                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Text generation                 | WordPress AI Client via `Settings > Connectors`, including connector-backed providers such as Anthropic, Google, or OpenAI when installed/configured. On WordPress.com / managed hosting where the `ai` feature plugin is unavailable, falls back to Jetpack AI over the existing Jetpack connection (no connector or API key). |
| Embeddings for Qdrant           | Cloudflare Workers AI settings in `Settings > Flavor Agent`.                                                                                                             |
| Vector-backed pattern retrieval | Qdrant plus Cloudflare Workers AI embeddings.                                                                                                                            |
| Private pattern search          | Cloudflare AI Search pattern retrieval backend.                                                                                                                          |
| WordPress docs grounding        | Trusted `developer.wordpress.org` chunks through the built-in public Cloudflare AI Search endpoint, with best-effort cache-first lookup (a miss runs one bounded foreground search; failures never block recommendations). |
| Optional core-roadmap guidance  | GitHub public roadmap fetch only when the developer opt-in filter is enabled.                                                                                            |

## Known limitations

- Navigation recommendations are advisory-only. There is no validated navigation apply/undo contract in `0.1.0`.
- External applies cover four lanes: Global Styles / Style Book, `wp_template`, `wp_template_part`, and post blocks. Block-level, content, navigation, and pattern external applies are C2+ work and are not exposed in `0.1.0`.
- Ring III attestation covers three of the four lanes. The post-blocks lane is not attested, because its non-public `post_content` is incompatible with the public subject-state contract.
- Pattern recommendations rank and explain native patterns but do not own pattern insertion, pattern undo, or Gutenberg pattern-registry mutation.
- Content recommendations produce editorial guidance and generated text only; there is no automatic post-content patch/apply flow.
- AI Activity is an approval/audit/provenance surface, not a full observability product. It includes pending external style, template, template-part, and post-blocks apply decisions, selected-row actions, structured diff and before/after summaries, and a first rich visual diff layer for style-governance rows, but broader cross-operator workflows and deeper observability are deferred.
- Global Styles and Style Book suggestions are constrained to validated `theme.json` operations; stronger design-quality or accessibility-quality claims are intentionally deferred until deterministic validation expands.
