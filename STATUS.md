# Flavor Agent - Status

> Last updated: 2026-08-26

## Working

### Abilities API (WordPress 7.0+)

Flavor Agent defines 35 ability contracts. The 14 helper/search abilities register whenever the Abilities API is available; the six `preview-recommend-*` signature-only siblings register when the canonical WordPress AI contracts are available; the eight recommendation abilities plus seven governed external-apply abilities register only when the WordPress AI plugin feature contracts are available and the Flavor Agent feature is enabled through the AI plugin feature toggles. Useful recommendation and external-apply output still depends on the per-surface capability and backend gates documented in [`docs/reference/abilities-and-routes.md`](docs/reference/abilities-and-routes.md). The full contract — permissions, handlers, schemas, descriptions, and behavior annotations (`readonly`/`destructive`/`idempotent`/`openWorld`) — lives there too.

AI plugin [`1.3.0`](https://github.com/WordPress/ai/releases/tag/1.3.0) compatibility is documented and the Docker-backed WordPress 7.1 E2E harness passes with that release active (30/30). A real Anthropic-backed `flavor-agent/recommend-content` request resolved `claude-sonnet-4-6`, returned a schema-valid recommendation, and reported no unexpected runtime error on 2026-08-26; the sanitized record is [`docs/validation/2026-08-26-anthropic-connector-smoke.md`](docs/validation/2026-08-26-anthropic-connector-smoke.md). Flavor Agent now calls `wp_ai_client_prompt()` directly instead of the deprecated `AI_Service` / `get_ai_service()` layer and explicitly maps its public snake_case generation options to the AI Client SDK's camelCase `ModelConfig` keys. The release's Custom Abilities opt-in gate applies to the AI plugin's custom abilities, not Flavor Agent's registrations, and public `log_ai_request()` complements the existing request-log bridge and local diagnostics. Embedding helpers are not usable on supported WordPress 7.0/7.1 because [`#946`](https://github.com/WordPress/ai/pull/946) disables `SDK_Overlay`; Flavor Agent retains plugin-owned embeddings and retrieval.

### REST API

All nine REST route paths under `/flavor-agent/v1/` are working. Recommendation surfaces and external-agent governed-apply read/list/undo flows use the WordPress Abilities API instead. Permissions and handlers are documented in [`docs/reference/abilities-and-routes.md`](docs/reference/abilities-and-routes.md).

- **4 activity/coordination route paths / 6 methods**: GET/POST `activity` (contextual editor/theme capability; sitewide GET requires `manage_options`), POST `activity/{id}/undo` (contextual), POST `activity/{id}/decision` (`manage_options` plus the row's mutation capability), and POST/DELETE `activity/{id}/claim` for advisory review claims
- **1 admin route path / 2 methods**: POST `sync-patterns` queues the sync job (`manage_options`); GET `sync-patterns` returns current sync state for polling (`manage_options`)
- **4 public attestation GET paths**: `attestations/{id}`, `attestations/{id}/verification`, `attestations/{id}/subject-state`, and `attestations/keys` expose public-safe signed evidence and lane-specific live subject state for eligible style, template, and template-part applies

- Playground smoke harness flake, recorded per `docs/reference/cross-surface-validation-gates.md` rather than silently absorbed: the CI `Playground smoke suite` job has failed **8 of 49 completed runs (16.3%)** since the workflow was created 2026-07-20 (runs 29781491037, 30322550003, 30322891050, 30334937983, 30337422985, 30786137389, 31864133215, 31906757683). The cause is WordPress Playground infrastructure, not plugin code. Under the block editor's concurrent boot burst the PHP instance pool intermittently fails to hand out an instance; `@php-wasm/universal@3.1.13` answers with `PHPResponse.forHttpCode( 500 )` — an empty header map plus a 21-byte `Internal Server Error` body that Express then stamps `X-Powered-By: Express` — and discards the error object, so nothing is logged at any `--verbosity`. Verified by control experiment: stock Playground with **no plugin mounted** reproduces the signature (5/320 requests), and an interleaved A/B measured 52/320 faults with the plugin mounted against 51/320 without. When the fault lands on core `/wp/v2/block-patterns/patterns` the inserter is starved of patterns, which is what reds the pattern tests — the same test (`pattern surface smoke uses the inserter search to fetch recommendations`) failed this way on 2026-07-28 and twice on 2026-08-15, on three unrelated revisions, one of which was comment-only. `tests/e2e/test-fixtures.js` now records every 5xx as a report attachment, labels only the exact Express-backed signature as a Playground pool fault, and keeps mixed or non-matching failures product-visible. It deliberately does **not** fail an otherwise-passing test, and no CI retries were added: Playwright reports `flaky` as a separate non-failing count, so bare retries would convert a genuine intermittent regression into a recorded green.
